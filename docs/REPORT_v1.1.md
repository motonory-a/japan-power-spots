# v1.1 作業報告（2026年11月3日）

## 1. 現状調査（main ブランチ 2440ae8 時点）

リポジトリにはコミットが2件、ファイルは index.html の1つだけでした（約11KB、HTML・CSS・JavaScript が1ファイルにまとまった形）。以前の「v2 ZIP」にあった構成ではなく、この1ファイル版が公開中の実体です。

ブラウザ（PC幅1280px・スマホ幅390px）で次の操作を確認しました。

- 生年月日と都道府県を入れて診断 → 結果5件が表示される。コンソールエラーなし。
- 数秘ナンバーの計算は正しい（例：1974-04-15 → 1+9+7+4+0+4+1+5=31 → 4）。
- 未入力のときはブラウザの警告ダイアログ（alert）が出る。

動きはしますが、次の点が気になりました。

| No | 内容 | 影響 |
|---|---|---|
| 1 | 数秘が一致すると一律100点、近さは最大40点なので、数秘一致の遠いスポットが近いスポットより必ず上になる（東京から409kmの高野山が90kmの鹿島神宮より上） | 推薦の偏り |
| 2 | 各スポットに割り当てた数秘ナンバー（numbers）に根拠がない。画面上でもデモとの区別が弱い | 誤解のおそれ |
| 3 | 願い・交通手段の入力がない。方角の表示がない | 仕様書の要件不足 |
| 4 | 診断結果が地図に出ない。「地図で確認」は外部のGoogleマップに飛ぶだけ | 使い勝手 |
| 5 | 入力エラーが alert 表示。未来日付も日付欄で選べてしまう（押した後には弾かれる） | 使い勝手 |
| 6 | 存在しない日付・1900年より前の日付のチェックがない | 軽微 |
| 7 | Leaflet をCDNから読み込む際の改ざん防止（SRI）が付いていない | 安全面・軽微 |
| 8 | CDNが落ちると地図部分でエラーになり、その後の処理も止まる | 障害時 |

## 2. 修正方針

- 公開中の main には直接触れず、開発用ブランチ（dev/v1.1）で作業。
- 1ファイルを、画面・見た目・計算・地図・データ・設定に分けた。外部読込はすべて相対パス。
- 数秘の計算式は現行のまま残す（暫定ロジック）。九星気学は実装済みと表示しない。
- 推薦は「数秘30・願い40・近さ20・データ信頼性10」の100点満点。配分は config.js で変えられる。
- 願いを1つ以上選んだときは、その願いに1つでも当てはまるスポットを先に並べる。
- デモデータは信頼性0点・「デモデータ（参考候補・内容未確認）」と全カードに表示。
- 非公開・立入禁止の状態を持つスポットは推薦から外す仕組みを用意（いまのデモ8件は全件公開扱い）。

## 3. 今回の変更内容

- 願い・体験の複数選択（恋愛・金運・学業・仕事・健康祈願・浄化・自然・滝・登山・森林・神社・寺院）
- 交通手段（公共交通・車・徒歩）。直線距離の目安で近さを判断し、所要時間は出さない
- 推薦カードに順位、相性の説明、方角（8方位）と直線距離、スコア、データの状態、根拠と点数の内訳
- 「この地図で見る」でページ内の地図に移動してポップアップ表示。経路はGoogleマップへ（交通手段を引き継ぐ）
- 診断結果を地図に順位番号つきで表示、出発地の目安も表示。種類ごとに色分けと凡例
- 入力エラーは画面内に表示（alert廃止）。未来日付・存在しない日付・1900年より前をチェック
- 試作版・デモデータのお知らせ、お出かけ前の注意事項
- Leaflet にSRIを付与。CDNが読めないときは「地図を読み込めませんでした」と出し、診断と検索は動く
- データの項目名を仕様書の必須スキーマに合わせた（Phase 2 の全国データにそのまま差し替えられる形）

## 4. テスト結果

### 計算部分の自動テスト（tests/run-tests.js）

33件すべて成功。主な内容：

- 数秘：1974-04-15→4、1999-12-31→8、1989-09-29→2、1900-01-01→3、1900〜2026年の日付で必ず1〜9
- 日付チェック：うるう日（2024-02-29）は有効、2023-02-29は無効、当日は有効、翌日は無効
- 距離：東京都庁→大阪府庁 約397km
- 方角：真北・真東・真南、境界（22.5°は北東、337.5°は北）、東京→出雲大社は西
- 推薦：点数の合計と内訳が一致、0〜100の範囲、願い一致の優先、非公開・立入禁止の除外、47都道府県すべてで計算可
- データ：必須項目・ID重複・座標範囲・都道府県コード
