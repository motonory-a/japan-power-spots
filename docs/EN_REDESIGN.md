## 1. 今の英語版の作りと問題点(調べた結果)

**今あるもの**
- トップ /en/ … 1ページにすべてが入っている(スマホで縦約12,000px)。中身は、願い選び → 診断 → 結果 → 旅程づくり → マイリスト → モデルコース → グルメ案内 → 参拝の作法 → このサイトについて → アッキー紹介
- スポットのページ /en/spots/ … 1,406ページ。毎週月曜に自動で作り直している(en-pages)
- グルメ図鑑・食べ方ガイド・門前グルメ・ランキング … /en/ の中に別ページとしてある

**問題点**
1. **ほかの4言語が英語版にぶら下がっている。**韓国語・中国語・フランス語・スペイン語のトップは、英語版トップの文章を機械的に置き換えて作っている(scripts/build_lang_pages.js)。英語版の文章を1つ変えるだけで、4言語の作成が止まる。→ いちばん注意が必要な点
2. 1ページが長すぎる。知りたいこと(行き方・作法・どこへ行くか)にたどり着きにくい。
3. 入口が「生年月日で診断」中心。日本に来る外国人がまず知りたいことは「東京や京都から行ける、有名で外せない場所」「作法」「回り方」で、診断は2番目の楽しみ(推測)。
4. (訂正 2026-11-27)スポットのページの写真は、開いたときにブラウザが Wikidata/Commons から読み込んで出している。最初の調べでは、作業環境からそこへつながらないため「写真がない」と見誤った。
5. 「このサイトについて」の欄の文字の並びが崩れている。アッキーの紹介写真が出ていない(手元で表示して確認)。
6. 検索から人が入る「都市ごとのまとめページ」(例:Kyoto power spots)がない。

## 2. 作り方の考え方:「土台は1つ、見せ方は国ごと」

### 土台(全言語で共通、1か所で管理)
| もの | 中身 | 置き場所 |
|---|---|---|
| スポットのデータ | 場所・種類・ご利益・地図・確認済み情報 | 今の data/(変えない) |
| 計算の仕組み | 距離・方位・九星気学・数秘 | 今の assets/js/(変えない) |
| 言語ごとの名前と説明文 | スポット名、短い説明 | 新しく data/i18n/spots-en.json(韓国語版は spots-ko.json…) |
| 画面の部品 | 診断・旅程・マイリスト・地図の動き | 新しく assets/js/edition/(全言語で1つ。文字だけ言語ファイルから読む) |

### 見せ方(国ごとに変える)
- 言語ごとの設定ファイル 1枚(data/editions/en.json):トップに出すおすすめスポット、都市ページの並び、強く見せる中身、文章の調子
- ページの文章(案内・作法・回り方)は、その国の人向けに一から書く(訳さない)

### ページを作る仕組み
- 新しいプログラム scripts/build_edition.js が、「共通データ+言語の設定+ページのひな形」から、その言語の全ページを作る
- 英語で型を決めれば、韓国語は設定ファイルと文章を足すだけで同じ仕組みで作れる

## 4. 公開中のサイトを壊さない進め方

1. **ほかの4言語を英語版から切り離す(見た目は何も変わらない)。**今の英語版トップを「ひな形」として別の場所に保存し、build_lang_pages.js はそれを使うように直す。韓国語などは、作り直すまで今のまま動く。
2. **新しい英語版は /en-next/ で作る。**検索には出さない(noindex)。アッキーがスマホで確認する。
3. **OKが出たら入れ替える。**スポットのページ・グルメ・ランキングの住所(URL)は変えない。トップの中の「#planner」などの飛び先は、新しいページへ案内する。
4. どのページにも、Googleアナリティクスのタグ(G-CX2WH9VGQ5)とホーム画面アプリ(PWA)の設定を入れる。sw.js の版を上げる。
5. 毎週月曜の自動作成(en-pages)は、新しい仕組みに切り替えるまで止めない。切り替えるときに一緒に直す。
